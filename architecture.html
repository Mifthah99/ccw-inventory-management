Factory Inventory Management System

Architecture overview of the workshop demo: a Vue 3 single-page app talking to a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

Overview System Data flow Frontend Backend Data Key files Gaps

Overview

Two processes, one direction of dependency: the browser app calls a REST API; the API reads datasets that were loaded into Python lists at startup.

Frontend

Vue 3 + Vite

  • Port 3000
  • vue-router, axios
  • Composables for shared state (no Pinia/Vuex)
  • Custom SVG charts, English/Japanese i18n
Backend

FastAPI + Uvicorn

  • Port 8001, docs at /docs
  • Pydantic response models
  • Filtering is plain Python list comprehensions
  • CORS open to all origins
Data

JSON in memory

  • 7 files in server/data/
  • Loaded once by mock_data.py
  • Read-only at runtime; resets on restart
  • Regenerated by generate_data.py

System architecture

Components and the boundaries between them.

Data flow

Every filter change travels the same path. Raw data lives in refs; everything displayed is derived from them in computed properties.

Example: user picks warehouse "Tokyo" on the Dashboard

  1. FilterBar writes selectedLocation = "Tokyo" in the shared useFilters state.
  2. The Dashboard watcher fires and calls getCurrentFilters(), which returns {warehouse, category, status, month?}.
  3. It runs getDashboardSummary, getOrders, getInventory and getBacklog together. api.js drops any filter equal to "all" from the query string.
  4. FastAPI runs apply_filters then filter_by_month over the in-memory lists and validates the result against the Pydantic model.
  5. The view stores the raw arrays in refs; KPI cards, charts and tables are computed properties over those refs, so the UI updates without any manual wiring.

Shared state

Composables

  • useFilters - four singleton refs (period, location, category, status), getCurrentFilters(), resetFilters()
  • useI18n - en / ja dictionaries, locale persisted in localStorage, currency follows locale (USD / JPY)
  • useAuth - hardcoded mock current user with language-aware fields and seed tasks

Components

  • FilterBar, ProfileMenu, LanguageSwitcher
  • Modals: Product, Inventory, Backlog, Cost, Tasks, ProfileDetails
  • utils/currency.js formats amounts for the active locale

Conventions

  • Raw API data in refs (allOrders, inventoryItems); derived data in computed properties.
  • Charts are hand-written SVG, layouts use CSS Grid; design tokens are slate/gray with green / blue / yellow / red status colors.
  • Styles live mainly in App.vue plus per-view scoped CSS. Tailwind is not installed in client/package.json.

Filter helpers

  • apply_filters - exact match on warehouse, case-insensitive on category and status; the value all is a no-op.
  • filter_by_month - accepts 2025-09 style months or Q1-2025 to Q4-2025, matched as a substring of order_date.
  • Inventory has no date field, so it cannot be filtered by month.

Tests

  • tests/backend/ - pytest + FastAPI TestClient, 40 tests across dashboard, inventory and misc endpoints.
  • Dev deps: pytest, pytest-asyncio, httpx, pytest-cov.
  • No frontend tests.

Data layer

mock_data.py reads each JSON file once at import and exposes the results as module-level lists. Nothing is ever written back, so the data resets on every restart.

Dashed lines are references by id. The remaining files flow into mock_data.py the same way. server/generate_data.py can rebuild the sample data across all months of 2025.

Gaps and inconsistencies found

Things in the code that do not line up. Useful starting points for workshop exercises.

Missing endpoints. api.js calls GET/POST /api/tasks, PATCH/DELETE /api/tasks/{id}, POST /api/purchase-orders and GET /api/purchase-orders/{backlog_item_id}, but none exist in main.py. The Tasks modal and purchase-order flow will get 404s.
Unused models. PurchaseOrder and CreatePurchaseOrderRequest are defined but not used by any route. purchase_orders.json is an empty list, so has_purchase_order is always false.
Unrouted view. Backlog.vue is never registered in the router; backlog data only appears through the Dashboard modal.
Inconsistent API access. Reports.vue calls axios directly with a hardcoded URL instead of going through api.js, and api.js itself hardcodes localhost:8001.
Duplicated logic. The quarterly report repeats the quarter-to-months mapping that already exists as QUARTER_MAP.
No persistence. Everything is in memory and read-only, and the documentation (CLAUDE.md, README) says there is no database. There is no SQLite or other storage in the backend.
